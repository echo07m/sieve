# 工具链集成指南

「剧合规（Sieve）」作为短剧生产工具链中的**合规预检环节**，通过以下标准与上下游工具衔接：

| 衔接面 | 标准/格式 | 用途 |
| --- | --- | --- |
| 接口契约 | **OpenAPI 3.0**（`GET /api/v1/openapi.json`） | 任意语言生成客户端、契约测试 |
| 报告交换 | **SARIF 2.1.0** | GitHub Code Scanning、IDE、安全平台导入 |
| CI 报告 | **JUnit XML** | Jenkins / GitLab CI / Azure DevOps 测试结果展示 |
| 管线命令行 | **sieve-cli**（`cli/sieve-cli.mjs`） | 任意管线/CI 嵌入，退出码做合规门禁 |
| 异步回调 | **Webhook**（HMAC-SHA256 签名） | 检测完成主动推送到自有系统 |
| 剧本输入 | **Sieve Script JSON** | 编剧/资产管理系统的标准化剧本交换格式 |

---

## 1. 剧本输入标准：Sieve Script JSON

编剧工具、剧本管理系统导出以下 JSON 即可直接送检（sieve-cli 与 API 均支持）：

```json
{
  "episodes": [
    { "episodeNo": 1, "title": "第一集标题", "content": "本集剧本全文……" },
    { "episodeNo": 2, "title": "第二集标题", "content": "……" }
  ]
}
```

纯文本亦可：用「第N集」标记分集，引擎自动做集-句级解析。

## 2. sieve-cli：管线嵌入

零依赖（Node.js ≥ 18），从仓库直接取用：

```bash
# 同步检测（小剧本）
node cli/sieve-cli.mjs --file 剧本.txt \
  --key $SIEVE_API_KEY --endpoint https://your-sieve.com \
  --platform hongguo --fail-on block

# 大剧本走异步 + 轮询
node cli/sieve-cli.mjs --file 剧本.json --async --fail-on high

# 输出 SARIF / JUnit 供 CI 消费
node cli/sieve-cli.mjs --file 剧本.txt --format sarif --output results.sarif
node cli/sieve-cli.mjs --file 剧本.txt --format junit --output results.xml
```

**退出码**：`0` 通过 ｜ `1` 执行错误 ｜ `2` 命中 ≥ 阈值（合规门禁拦截）

## 3. GitHub Actions：剧本入库即检

```yaml
# .github/workflows/script-precheck.yml
name: 剧本合规预检
on:
  push:
    paths: ['scripts/**']   # 剧本目录变更触发

jobs:
  precheck:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 20 }

      - name: Sieve 合规预检（门禁：阻断级命中即失败）
        env:
          SIEVE_API_KEY: ${{ secrets.SIEVE_API_KEY }}
        run: |
          for f in scripts/*.txt; do
            node cli/sieve-cli.mjs --file "$f" \
              --endpoint https://your-sieve.com \
              --fail-on block --format sarif --output "$f.sarif"
          done

      - name: 上传 SARIF 到 Code Scanning（可选）
        if: always()
        uses: github/codeql-action/upload-sarif@v3
        with:
          sarif_file: scripts/
```

GitLab CI / Jenkins 同理：执行 sieve-cli 并以 `--format junit --output` 产物做测试报告归档。

## 4. Webhook 对接自有系统

异步检测完成后推送 `detect.done` / `detect.failed`。验签（务必）：

```
X-Sieve-Signature = "sha256=" + HMAC_SHA256(端点签名密钥, 原始请求体)
```

详见 [API 文档](./API.md#webhook-回调)。

## 5. 报告导出格式对照

| 格式 | 获取方式 | 下游工具 |
| --- | --- | --- |
| Word (.docx) | 报告页「导出Word」 | 存档、送审附件、商务交付 |
| SARIF | 报告页「导出SARIF」/ sieve-cli | GitHub Code Scanning、VSCode SARIF Viewer |
| JUnit XML | 报告页「导出JUnit」/ sieve-cli | Jenkins/GitLab/Azure 测试报告 |
| JSON | `/api/v1/detect` 响应 | 自有系统二次加工 |
| Webhook 推送 | `/webhooks` 配置 | 制作管理系统（ERP/PM 工具） |
