# 工具链集成指南

「剧合规（Sieve）」作为短剧生产工具链中的**合规预检环节**，通过以下标准与上下游工具衔接：

| 衔接面 | 标准/格式 | 用途 |
| --- | --- | --- |
| 接口契约 | **OpenAPI 3.0**（`GET /api/v1/openapi.json`） | 任意语言生成客户端、契约测试 |
| 报告交换 | **SARIF 2.1.0** | GitHub Code Scanning、IDE、安全平台导入 |
| CI 报告 | **JUnit XML** | Jenkins / GitLab CI / Azure DevOps 测试结果展示 |
| 管线命令行 | **sieve-cli**（`cli/sieve-cli.mjs`） | 任意管线/CI 嵌入，退出码做合规门禁 |
| 异步回调 | **Webhook**（HMAC-SHA256 签名） | 检测完成主动推送到自有系统 |
| 剧本输入 | **Sieve Script JSON** | 编剧/资产管理系统的标准化剧本交换格式 |
| AI 编剧助手 | **MCP Server**（`cli/sieve-mcp.mjs`） | Kimi/Claude 等 AI 助手边写边检 |
| CI 官方动作 | **GitHub Action**（`uses: echo07m/sieve@v1`） | 一行接入，无需手写脚本 |
| 分镜拆解 | **Sieve Storyboard JSON**（`POST /api/v1/storyboard`） | 剧本 → 分镜表 + 逐镜 agentPrompt，衔接视频生成 |

---

## 1. 剧本输入标准：Sieve Script JSON

编剧工具、剧本管理系统导出以下 JSON 即可直接送检（sieve-cli 与 API 均支持）：

```json
{
  "episodes": [
    { "episodeNo": 1, "title": "第一集标题", "content": "本集剧本全文……" },
    { "episodeNo": 2, "title": "第二集标题", "content": "……" }
  ]
}
```

纯文本亦可：用「第N集」标记分集，引擎自动做集-句级解析。

## 2. sieve-cli：管线嵌入

零依赖（Node.js ≥ 18），从仓库直接取用：

```bash
# 同步检测（小剧本）
node cli/sieve-cli.mjs --file 剧本.txt \
  --key $SIEVE_API_KEY --endpoint https://your-sieve.com \
  --platform hongguo --fail-on block

# 大剧本走异步 + 轮询
node cli/sieve-cli.mjs --file 剧本.json --async --fail-on high

# 输出 SARIF / JUnit 供 CI 消费
node cli/sieve-cli.mjs --file 剧本.txt --format sarif --output results.sarif
node cli/sieve-cli.mjs --file 剧本.txt --format junit --output results.xml

# 查询当前 Key 的订阅额度用量
node cli/sieve-cli.mjs --usage

# 编剧软件格式转换：Fountain / Final Draft(.fdx) → Sieve Script JSON
node cli/sieve-cli.mjs --file 剧本.fountain --convert fountain > 剧本.json
node cli/sieve-cli.mjs --file 剧本.fdx --convert fdx > 剧本.json
```

**退出码**：`0` 通过 ｜ `1` 执行错误 ｜ `2` 命中 ≥ 阈值（合规门禁拦截）

**编剧格式转换说明**：`--convert` 支持 [Fountain](https://fountain.io) 纯文本标记（自动识别场景头 INT./EXT.、角色台词——含中文角色名——以及 TO: 转场）与 Final Draft `.fdx`（Scene Heading / Character / Dialogue / Action / Transition 段落）。转换结果为 Sieve Script JSON，可直接作为 `--file` 的输入送检，实现「编剧软件导出 → 预检」零改造衔接。

## 3. GitHub Actions：剧本入库即检

### 3.1 官方 Action（推荐，一行接入）

```yaml
# .github/workflows/script-precheck.yml
name: 剧本合规预检
on:
  push:
    paths: ['scripts/**']   # 剧本目录变更触发

jobs:
  precheck:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Sieve 合规预检（门禁：阻断级命中即失败）
        uses: echo07m/sieve@v1
        with:
          api-key: ${{ secrets.SIEVE_API_KEY }}
          endpoint: https://your-sieve.com     # 自建实例时必填，官方 SaaS 可省略
          files: 'scripts/*.txt'                # 支持空格分隔多个 glob
          platform: universal
          fail-on: block                        # block | high | notice | never
          async: false                          # 大剧本可开启异步模式
          sarif-output: results.sarif           # 可选：汇总 SARIF 输出路径

      - name: 上传 SARIF 到 Code Scanning（可选）
        if: always()
        uses: github/codeql-action/upload-sarif@v3
        with:
          sarif_file: results.sarif
```

Action 输出 `breached`（true/false）可在后续步骤中做条件判断；门禁被触发时 job 以退出码 2 失败。

### 3.2 手写脚本方式（GitLab CI / Jenkins 同理）

```yaml
      - name: Sieve 合规预检
        env:
          SIEVE_API_KEY: ${{ secrets.SIEVE_API_KEY }}
        run: |
          for f in scripts/*.txt; do
            node cli/sieve-cli.mjs --file "$f" \
              --endpoint https://your-sieve.com \
              --fail-on block --format sarif --output "$f.sarif"
          done
```

执行 sieve-cli 并以 `--format junit --output` 产物做测试报告归档。

## 4. Webhook 对接自有系统

异步检测完成后推送 `detect.done` / `detect.failed`。验签（务必）：

```
X-Sieve-Signature = "sha256=" + HMAC_SHA256(端点签名密钥, 原始请求体)
```

详见 [API 文档](./API.md#webhook-回调)。

## 5. 报告导出格式对照

| 格式 | 获取方式 | 下游工具 |
| --- | --- | --- |
| Word (.docx) | 报告页「导出Word」 | 存档、送审附件、商务交付 |
| SARIF | 报告页「导出SARIF」/ sieve-cli | GitHub Code Scanning、VSCode SARIF Viewer |
| JUnit XML | 报告页「导出JUnit」/ sieve-cli | Jenkins/GitLab/Azure 测试报告 |
| JSON | `/api/v1/detect` 响应 | 自有系统二次加工 |
| Webhook 推送 | `/webhooks` 配置 | 制作管理系统（ERP/PM 工具） |

## 6. 用量查询：`GET /api/v1/usage`

管线在批量送检前可先查询额度，避免任务堆积：

```bash
curl -H "Authorization: Bearer $SIEVE_API_KEY" https://your-sieve.com/api/v1/usage
```

```json
{
  "planCode": "pro", "planName": "专业版", "status": "active",
  "unlimited": false, "quotaTotal": 1000, "quotaUsed": 7,
  "quotaRemaining": 993, "expiresAt": "2027-09-01T00:00:00.000Z"
}
```

sieve-cli 等价命令：`node cli/sieve-cli.mjs --usage`。

## 7. MCP Server：AI 编剧助手边写边检

`cli/sieve-mcp.mjs` 是标准 MCP（stdio）服务，Kimi、Claude 等支持 MCP 的 AI 编剧助手可在写作过程中直接调用合规检测——写完一段检一段，问题台词当场改写。

客户端配置示例：

```json
{
  "mcpServers": {
    "sieve": {
      "command": "node",
      "args": ["/path/to/sieve/cli/sieve-mcp.mjs"],
      "env": {
        "SIEVE_API_KEY": "sk-你的APIKey",
        "SIEVE_ENDPOINT": "https://your-sieve.com"
      }
    }
  }
}
```

提供 4 个工具：

| 工具 | 说明 |
| --- | --- |
| `sieve_detect` | 同步检测，秒级返回（命中精确到集-句，附整改建议） |
| `sieve_detect_async` | 大剧本异步提交，返回 taskNo |
| `sieve_get_task` | 轮询异步任务状态与结果 |
| `sieve_usage` | 查询订阅额度用量 |

## 8. 分镜拆解：剧本 → 视频生成流水线

送检前置环节。剧本拆成结构化分镜表，每镜附 `agentPrompt`（面向即梦/可灵/Runway 等文生视频模型），让视频生成 agent 直接消费：

```bash
# API（不消耗检测配额，共享 60 次/分钟限流）
curl -X POST -H "Authorization: Bearer $SIEVE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"workTitle":"闪婚老公是总裁","scriptText":"第1集 ……"}' \
  https://your-sieve.com/api/v1/storyboard

# CLI（--output .json 存分镜表，.txt 存逐镜提示词包）
node cli/sieve-cli.mjs --file 剧本.txt --storyboard --output 分镜.json
node cli/sieve-cli.mjs --file 剧本.txt --storyboard --output 提示词包.txt
```

**Sieve Storyboard JSON** 每镜字段：

| 字段 | 说明 |
| --- | --- |
| `shotNo` / `episodeNo` / `scene` | 镜号（全剧连续）/ 集 / 场景 |
| `shotType` | 景别：`long` 远景 / `full` 全景 / `medium` 中景 / `close` 近景 / `extreme_close` 特写 |
| `cameraMove` | 运镜：`fixed` / `push` / `pull` / `pan` / `follow` / `handheld` |
| `visual` / `dialogue` / `character` | 画面内容 / 台词 / 出场角色 |
| `durationSec` / `mood` | 时长估算（中文台词 4.5 字/秒）/ 情绪氛围 |
| `agentPrompt` | 单镜视频生成提示词（竖屏 9:16、景别运镜、情绪氛围、网剧色调） |

拆解规则（确定性、可复现）：【场景】/Fountain 场景头 → 先插远景交代镜；台词行 → 近景/中景对话镜（情绪激烈给特写）；旁白动作行 → 中景/全景，超 60 字拆两镜；动作强度词触发运镜建议（追逐→跟随、打砸→手持等）。

MCP 工具 `sieve_storyboard` 同样可用，AI 编剧助手写完剧本可直接拆镜。
