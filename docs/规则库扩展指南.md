# 规则库扩展指南

> 面向规则贡献者：如何向「剧合规」规则库新增/修订检测规则。
> 规则库是本项目的核心资产，质量要求高于一般代码贡献，请逐节阅读。

## 规则数据结构

规则定义见 `db/schema.ts` 的 `rules` 表，种子数据位于 `api/engine/seedData.ts`（类型 `InsertRule`）。逐字段说明：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `ruleCode` | string，唯一 | 规则编号，命名规范：`R{类}-年份-序号`，如 `R2-2026-003`。`{类}` 为 1–8，对应八大类别顺序（见下表）；序号在同类同年份内递增，不可复用已废弃编号 |
| `version` | string | 规则自身版本，默认 `"1.0.0"`，修订时递增 |
| `status` | `active` / `disabled` | 默认 `active`；下线规则用 `disabled`，不要删除（保留存证可追溯性） |
| `category` | 枚举 | 八大类别之一，见下表 |
| `name` | string | 规则名称，简洁描述判定对象，如「性暗示与擦边描写」 |
| `severity` | `block` / `high` / `notice` | 严重级别：`block` 阻断级红线（必须整改）；`high` 高危；`notice` 提示级（设定本身不必然违规，提示自查） |
| `sourcePolicy` | string | 政策文件名称，如「广电总局有害低俗与侵权盗版专项治理部署」 |
| `sourceClause` | string | 具体条款定位，如「8类问题之二：软色情擦边」 |
| `originalText` | string | 政策原文摘录（直引），不得改写 |
| `sourceConfidence` | `official_text` / `vendor_interpretation` | 标注纪律见下文「来源置信度」 |
| `scope` | string[] | 作用范围：`title` / `episode_title` / `dialogue` / `narration` / `promo_copy` / `full_text`。`full_text` 等价于标题+对白+旁白 |
| `keywords` | string[] | 关键词通道：出现即命中（字面包含匹配） |
| `patterns` | string[] | 正则通道：JS 正则（`u` 标志），如 `"未成年.{0,12}(侵害\|虐待)"`；非法正则会静默跳过，务必自测 |
| `cooccurrence` | object[] | 共现通道：`{ groupA: string[], groupB: string[], window: number }`，A 组任一词与 B 组任一词在 `window` 字符内共现才命中 |
| `baseConfidence` | decimal(3,2) | 基础置信度 0.00–1.00，字符串形式如 `"0.80"`；参考：阻断级 0.90+，高危 0.80 左右，提示级 0.70 左右 |
| `remediationTemplate` | string | 整改建议模板，可用 `{span}` 占位命中片段；必须写明依据出处与可执行的整改方向 |
| `platformOverrides` | object | 平台差分：`{ hongguo: { severity: "block", note: "红果4月起口径加码" } }`，键为平台标识（hongguo/fanqie/kuaishou/wechat_mini 等） |

### 三通道写法示例

```ts
{
  ruleCode: "R2-2026-003",
  version: "1.0.0",
  category: "soft_porn",
  name: "示例：擦边互动暗示",
  severity: "high",
  sourcePolicy: "广电总局有害低俗与侵权盗版专项治理部署",
  sourceClause: "8类问题之二：软色情擦边",
  originalText: "聚焦软色情擦边等8类问题",
  sourceConfidence: "official_text",
  scope: ["dialogue", "narration", "full_text"],
  keywords: ["宽衣解带"],                                   // 关键词：字面命中
  patterns: ["(喘息|呻吟).{0,8}(娇媚|暧昧)"],               // 正则：距离约束
  cooccurrence: [
    { groupA: ["酒店", "卧室"], groupB: ["孤男寡女", "衣衫不整"], window: 60 }, // 60字内共现
  ],
  baseConfidence: "0.80",
  remediationTemplate:
    "命中软色情擦边判定（依据：专项治理8类问题之二）。建议删除「{span}」相关暗示描写，改为情节推进型表达。",
  platformOverrides: {
    hongguo: { severity: "block", note: "红果口径加码，擦边直接驳回" },
  },
}
```

三条通道是"或"关系：任一通道命中即产生一条命中记录。建议组合使用 —— 关键词保证召回、正则约束距离/搭配、共现降低单字词误报。

### 来源置信度标注纪律

- `official_text`：**仅用于政策原文直引**，`originalText` 必须是原文摘录。
- `vendor_interpretation`：企服/行业解读口径、平台非公开审核经验。使用此值时，`originalText` 或 `remediationTemplate` 中**必须注明"以广电总局原文为准"**。
- 没有可靠出处的规则不要合入底座库；企业内部加严需求请走「自定义规则」功能（F13），不进公共种子。

## 新增规则步骤

1. 在 `api/engine/seedData.ts` 的 `seedRules` 数组中追加规则（按类别分区注释排列，与现有结构保持一致）。
2. 如需发版，bump 文件顶部 `RULE_SEED_VERSION`（如 `2026.09-v2`）。
3. 启动/重启服务时种子以**增量方式**自动入库：只写入新 ruleCode 或更新已有条目，**无需数据库迁移，也无需修改引擎代码**。
4. IP 参照库与平台配置同理，分别改 `ipSeedData.ts` / `platformSeedData.ts`。

## 测试方法

构造**最小样例剧本**验证命中，两步：

1. 本地起服务后在「送检」页粘贴样例剧本，确认：应命中的规则命中、集-句定位正确、严重级别与平台差分符合预期。
2. 同时验证**不误报**：构造同类别但合规的对照文本，确认无命中。

样例剧本格式（parser 按集切分）：

```
第1集
△旁白：……
张三：对白……
第2集
……
```

PR 中请粘贴样例片段 + 实际命中结果截图/文本，便于评审复核。

## 质量要求

- [ ] 每条规则附**明确政策出处**（sourcePolicy + sourceClause + originalText 原文摘录）
- [ ] 解读口径一律标 `vendor_interpretation` 并注明"以广电总局原文为准"
- [ ] ruleCode 符合 `R{类}-年份-序号` 规范且不与现有编号冲突
- [ ] 正则已实际测试（非法正则会静默跳过！）
- [ ] remediationTemplate 给出可执行整改方向，而非空泛警告
- [ ] 已用样例剧本验证命中与对照不误报
- [ ] 平台差分（platformOverrides）注明口径来源与生效时间
